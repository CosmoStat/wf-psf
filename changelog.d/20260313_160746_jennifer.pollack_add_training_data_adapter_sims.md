### Breaking changes

Migration summary:
- Replace dataset loading via `DataConfigHandler` with `DataAdapterFactory.build(...)`.
- Update configuration files to use `n_bins_lambda`.
- Ensure dataset fields follow canonical names or configure them via `canonical_keys`.

- `DataConfigHandler` no longer loads or adapts datasets. It is now limited to parsing, normalizing, and validating data configuration parameters. Dataset loading and preprocessing are handled by the new `DataAdapter` system.
- The deprecated `data_handler` module has been removed. All training, metrics, and inference pipelines now use `DataAdapter` or `DataAdapterFactory` for dataset access.
- Code that previously relied on `DataConfigHandler` returning datasets must now explicitly construct a `DataAdapter`.
- Previous configuration files are no longer compatible:
  - `training_config.yaml` and `metrics_config.yaml` must replace `n_bins_lda` with `n_bins_lambda`.
  - The previous `data_config.yaml` example has been removed. Users must update their data configuration files to match the schema exposed via `DataConfigHandler.params`.
- Example configuration files demonstrating the new supported formats are provided:
  - `data_complete_config.yaml` – configuration for loading a complete dataset and converting into train and test datasets.
  - `data_split_config.yaml` – configuration specifying separate train and test datasets.
  - `data_shallow_config.yaml` – configuration for shallow (without field "complete") dataset definitions and converting into train and test datasets.
- Dataset fields must follow canonical names defined in wf_psf.data.`constants.DEFAULT_CANONICAL_KEY`S`. Custom field names must be mapped via `canonical_keys` in the data configuration
- The `target_field` parameter in the data configuration specifies which key corresponds to the source images (formerly `stars` / `noisy_stars`.)
- `tf_psf_field` now explicitly concatenates `data.train_data` and `data.test_data` when generating Zernike ground-truth inputs. These must be retrieved from the normalized `DatasetContainer`.
- `train.get_loss_metrics_monitor_and_outputs` has been removed. Its functionality is now partially replaced by the `TrainingDataAdapter` and the `get_loss_and_metrics` factory.



### New features

- Add `NpyDatasetLoader` class to load `.npy` files containing datasets, supporting both simulated and real datasets. Expected keys: `positions`, `seds`, `sources` (configurable `target_field`), and optional `masks` and `zernike_prior`.
- Introduce `DataAdapter` and `DataAdapterFactory` to unify dataset handling across training and evaluation pipelines, supporting both split and complete datasets.
- Provide `SupportsParams` and `SupportsMetadata` protocols to allow external APIs to pass dataset parameters and metadata in generic objects.
- Add `normalize_data_envelope` and dataset introspection utilities (`DatasetUtils`) for consistent handling of dictionaries, dataclasses, or objects with attributes.
- Provide `DatasetContainer` (dict-like object) for storing structured datasets that also allows key/value transformations.
- Training pipeline now accepts complete datasets with normalized and canonicalized parameters.
- Logging added to dataset resolution and adapter construction steps for improved traceability.
- `TrainingDataAdapter` enables training-specific input/target handling with minimal boilerplate, supporting automatic stacking of source images and optional masks, positions and SEDs for loss computation.
- Pipeline now supports configurable splitting of complete datasets into training and test sets.
- Metrics monitoring is now configurable via the `monitor` field in the training configuration.
- Default data configuration parameters provided in `wf_psf.data.constants`.

### Internal changes

- Refactor data loading and type conversion pipeline to integrate with `DataAdapter`.
- `DataConfigHandler` now only normalizes configuration parameters and applies defaults automatically.
- Added `constants` file storing canonical and optional dataset keys, default train split fraction, and random seed.
- Dataset splitting and handling of complete datasets streamlined through the adapter and factory.
- Replaced `ZernikeInputs` and `ZernikeInputsFactory` with `ZernikeDataset`, providing access to Zernike-related inputs, priors via a `DatasetContainer`.
- `NpyDatasetLoader` now supports optional masks and priors configurable source field via `target_field`.
- Refactored training, metrics, and inference pipelines to use the new `DataAdapter` architecture.
- Updated `psf_model_physical_polychromatic` module to integrate `ZernikeDataset`.
- Added `TrainingDataAdapter` to handle stacking source images and masks for training, enabling the use of custom loss functions (e.g. `mask_mse`).
- Refactored `train.get_loss_and_metrics` to standalone factory function that returns fresh loss and metric objects per training cycle. It is invoked internally by `train.train`
- Training configuration handling refactored to extract and normalize data parameters via `DataConfigHandler.params`.
- Added `monitor` as a configurable training parameter.
-Updated unit and integration tests to reflect the new data handling, canonical/optional keys, and TensorFlow conversion routines.
